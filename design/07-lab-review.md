## (A) Security coverage gaps (most severe first)

**A1. Classified must be rejected and quarantined, not encrypted. GAP.** *00 Security; 04 intro* say the PDFs "may carry CUI … or classified markings" and run both through the same encrypt-and-store pipeline. CUI by definition excludes classified (32 CFR 2002.4(h)). Storing classified needs government approval (32 CFR 117.15(a)), and any system that processes it needs a managed program approved by a government authorizing official (117.18(a)(1), (e)). Encrypting it on a personal machine is still a spill. **Direction:** add a step 0 marking screen before any OCR or page split. Any classified banner or portion marking means stop: don't process the file, quarantine it untouched, and report it under a spill procedure (see A17). Remove "classified" from every "encrypt" sentence. [Lab L-S01, Defense D-G01, Offense C1.2, SQL 32]

**A2. Grok Build is a model-backed agent, so "no network" conflicts with its own context leaving the machine. It must never see real CUI or hold keys. GAP.** *00 Security "No network"; 04 Build agent* say CUI sessions run "fully local" with outbound network denied, but nothing says where the agent's model runs. Everything Grok Build reads (`cat` of a page, a failing CSV row, an error trace, a mismatch report) goes to its model provider. Either the deny breaks the agent, or a hole gets opened and CUI leaves in the prompt. The step 7 "fix the pipeline" loop makes this worse, because debugging means reading the bad data. It also has your shell, so it can read keys and the DB. Relevant rules: unauthorized external systems (NIST 800-171 r3 03.01.20, 03.16.03), least privilege (03.01.05), and no non-approved systems for CUI work (DoDI 5200.48 3.10.b). **Direction:** make it a hard rule. Grok Build builds and tests only on synthetic or public-release (Distribution A) fixtures. It runs as a separate OS user with no access to the real-CUI volume, keys or audit log. When debugging, it gets row IDs and error shapes, never content. A human runs the finished pipeline on real manuals, with no agent attached. [Lab L-S02, L-S17; Defense D-G02, D-G03, D-G16; Offense C1.1, C1.3, C4.6, C7.2]

**A3. Markings get stripped in 02 step 4 and nothing carries them forward. GAP.** *02 step 4 "Detect and strip the headers and footers"; 01 (no marking column anywhere); 05 outputs.* The CUI banner, portion markings and distribution statements live in headers and footers, so step 4 throws them away. The CSVs, carts and estimates are derived "working papers" and must be marked like the finished product (32 CFR 2002.20(k)). Other rules that apply: banner marking 2002.20(b), portion marking 2002.20(f), media marking 03.08.04, and DoD "CUI" banner/footer plus designation indicator (DoDI 5200.48 3.4.a, 3.4.f). **Direction:** capture markings and the distribution statement *before* stripping. Store them on `manual_revisions` and on each row, and put the highest marking on every CSV, screen, report and export. [Lab L-S04; Defense D-G09; SQL 31]

**A4. No FIPS-validated crypto, and pgcrypto isn't database encryption. GAP.** *00 "Encrypted database"; 04 Storage* name LUKS, FileVault and SQLCipher or pgcrypto, but no validated module. 03.13.11 says "FIPS-validated cryptography is recommended for the protection of CUI" and points to FIPS 140-3. pgcrypto only encrypts columns through SQL functions, and its key travels in SQL text, so it lands in statement logs and `pg_stat_*`. **Direction:** require CMVP-validated FIPS 140-3 modules and record the certificate numbers (which SQLCipher builds qualify is unverified). Remove the either/or and choose SQLCipher. [Lab L-S07; Defense D-G04, D-G05; Offense C5.4]

**A5. "Role-gated keys" can't be built as written, and there's no key management. GAP.** *00/04 Keys and access.* SQLCipher uses one key per database file, so any role that opens it can read every table. Generation, storage, rotation, recovery/escrow, revocation and destruction aren't defined (03.13.10). Lose the key and you lose the DB; a leaked key can't be retired. **Direction:** list the roles. Pick the model: one data key wrapped per role, or a separate DB per tier behind a broker process. Keep keys in the keychain, TPM or a hardware token, never in env vars, CLI arguments, shell history or agent context. Add rotation and split-custody recovery. [Lab L-S08; Defense D-G06; Offense C7.1, C7.2, C7.4; Python 28]

**A6. Backups aren't covered. GAP.** *Absent in all 8 files.* Time Machine, cloud backup, a plaintext `.dump`, or habitual `.bak` copies (this folder already has a `.bak-v1/`) would copy CUI outside the encrypted boundary. 03.08.09 requires backups to be encrypted. **Direction:** allow only encrypted backups, with a separate key, on approved offline media, marked and restore-tested. No plaintext dumps, no ad hoc `.bak` copies, and every backup logged. [Lab L-S09; Defense D-G07; Offense C8.1, C8.3]

**A7. Stop points and the network deny are enforced only by the prompt. GAP.** *00 Stop points; 00/04 "sandbox profile … hard control".* The agent reads and obeys these rules itself. Agent error or text injected through a manual can skip any of them, and nothing says who owns the sandbox profile. The deny also switches on only for sessions "touching CUI-marked" manuals, and the design has no marking detection. Network traffic should be denied by default at the boundary (03.13.06). **Direction:** enforce outside the agent. Use a VM or OS firewall rule owned by root that covers DNS and child processes, and treat every manual as CUI so the processing box is always offline. Verify with a connect test that has to fail. The load step refuses to run without your approval file listing the reviewed CSV hashes. [Lab L-S06, L-S15; Defense D-G15; Offense C2.9, C6.1, C6.2, C6.3, C9.3]

**A8. Manual text can steer the agent, and malformed PDFs can attack the parser. GAP.** *02 steps 1–2 and parsers.* PDFs can carry instructions in body text, hidden text layers, font remaps, image text, metadata or annotations, and nothing separates that content from instructions. Malformed PDFs or images can exploit Tesseract or the PDF library, or exhaust memory, as the user who holds the keys. CSV cells starting with `=`, `+`, `-` or `@` run as formulas when you open the review CSVs in a spreadsheet. **Direction:** keeping the agent off real content (A2) fixes the root cause. Also parse inside a throwaway no-network sandbox with resource limits, strip active content, metadata and annotations, flag pages where the text layer and OCR disagree, and escape formula characters. [Offense C2.1–C2.8, C3.1–C3.3, C3.5]

**A9. No stated basis for holding CUI on this machine. GAP.** *00 Security; 04 (absent).* NIST 800-171 applies to non-federal systems by contract (DoDI 5200.48 3.10.c, 5.1.a), personal systems are excluded (3.10.b), and there's no system security plan (03.15.02). **Direction:** write down the authority (contract, CUI categories, security plan) as a precondition. Until it exists, the pilot uses public-release manuals only. [Lab L-S03; Defense D-N04]

**A10. Export control isn't mentioned. GAP.** *00 Concept; 04 (absent).* Military maintenance manuals are ITAR technical data (22 CFR 120.33(a)(1): "operation, repair, testing, maintenance"). Export-controlled CUI carries an export-control warning (DoDI 5200.48 4.3.c), and access by foreign persons or a foreign-hosted model or cloud counts as release. **Direction:** record the distribution statement and export warning per manual, and limit people and model/cloud hosting to U.S. persons and U.S. systems. [Lab L-S05]

**A11. CUI copies escape the encrypted volume. GAP.** *04 Intermediate output (covers only "OCR output"); 02 Output artifacts; 00 step 7.* The CSVs, mismatch reports and diffs aren't named as sensitive. Tesseract, poppler and Python scratch files go to `/tmp`. Swap, hibernation and core dumps hold plaintext. Spotlight, thumbnails, spreadsheet autosave, iCloud, Time Machine, Universal Clipboard and Dropbox/Box/Drive clients all copy data, and no-cloud-sync is stated only for OCR output. Rules: 03.13.08 (protect in storage) and 03.13.04 (shared resources). **Direction:** name every derived artifact as CUI. Point TMPDIR at the encrypted volume, encrypt or disable swap and hibernation, and turn off core dumps and crash reporters. Keep data paths out of indexing and sync. Run the pipeline under a dedicated OS user with no cloud accounts, and review CSVs in a read-only offline viewer. [Lab L-S10; Defense D-G08, D-G10, D-G14; Offense C4.1, C4.2, C4.4, C4.5, C4.7; Python 29]

**A12. "Purge" isn't defined, and there's no sanitization. GAP.** *00/04 "purged once … validated".* Deleting a file on SSD or APFS doesn't erase it, and snapshots keep copies. CUI must be made "unreadable, indecipherable, and irrecoverable" (2002.14(f)(2); DoDI 5200.48 4.5), and media must be sanitized before reuse or disposal (03.08.03). **Direction:** purge by crypto-erase (destroy a per-batch key), turn off snapshots on that volume, and add an end-of-life disk wipe per NIST SP 800-88 Rev. 2. [Lab L-S11; Defense D-G11; Offense C4.3]

**A13. The audit log is thin, unprotected, and could leak CUI. GAP.** *00/04 "records every decryption event"; 01 (no audit table).* Only decrypts get logged. With SQLCipher, decryption happens when the DB opens, so an in-DB table can't record a failed open. Content requirements (03.03.02), UTC timestamps (03.03.07), protection from editing (03.03.08) and retention (03.03.03(b)) aren't addressed. Error logs with page text or SQL values become CUI themselves. Nothing records who approved which load. **Direction:** list the event types (authentication pass/fail, key operations, intake reject, load approval, export, backup, admin changes). Keep an append-only, hash-chained log outside the DB, written by a process your role user can't edit. Log only IDs and hashes, and add a `load_batches` record. [Lab L-S12; Defense D-G12; Offense C5.1–C5.3, C7.6; SQL 33, 34]

**A14. Authentication and roles are undefined, and so is write authorization. GAP.** *00/04 "Authenticate before decrypt"; 05 cap 10.* On one machine, your OS login is every role. 03.05.01 requires unique IDs and 03.05.03 requires MFA. Shop-floor feedback and inventory writes have no role check, so anyone can re-rank diagnoses. **Direction:** name the roles and the factor (for example one hardware key per role), set lockout and timeout (03.01.10, 03.01.11), and attribute every write. [Lab L-S13; Defense D-G13; Offense C7.3, C7.5]

**A15. There's no offline dependency or supply-chain plan. GAP.** *00 step 1; 04 Build agent.* With the network denied, installing `pip`/`brew` packages or Tesseract language data forces a choice between relaxing the deny and building blind (03.17.01, 03.17.03). **Direction:** phase 0 runs on a networked machine with no CUI and produces hash-pinned wheels, OS packages, language data and an SBOM. Move them over as a verified bundle, then lock the network. [Lab L-S14; Defense D-N01; Offense C6.4; Python 2]

**A16. Classified by compilation isn't considered. GAP.** *00 Concept.* DoDI 5200.48 3.7.c(2) names manuals and technical orders as information that "can become classified by compilation or aggregation", and 5.3.c requires contractors to watch for it. **Direction:** check the security classification guide (SCG) before going past the pilot, and add a stop point if compilation guidance is unknown. [Lab L-S18]

**A17. No incident or spill procedure. GAP.** *Absent.* Classified found at intake, CUI leaving through the agent, or lost media all need reporting (03.06.02; 117.18(b)(2) spill plans; DoDI 5200.48 3.9.e). **Direction:** write a one-page procedure covering who to notify, what to isolate and what not to touch. [Lab L-S16; Defense D-G17]

**A18. A poisoned manual can become "latest". GAP.** *03 step 4 "Default to the latest"; 02 step 5.* A forged revision block (future date or higher letter) makes every live query use the bad data. **Direction:** rank revisions only from an approved revision record checked against the official publication index, never from values parsed out of the PDF. [Offense C9.1]

### 01 Database schema

GAP.** *01 §2 `lead_time`, `on_hand_quantity`; 05 Inputs.* Neither value comes from a manual, and neither has units or a location. **Direction:** use a separate inventory table and feed that isn't revision-stamped. ## (D) Verdict

**NO. Grok Build would not know exactly what to build, and what it could build would be unsafe.**

Read as Grok Build would read them, the files give it a clear *idea* (concept, ten tables, pipeline order) but almost nothing it can *execute or check*. There's no stack to install, no offline way to install it, no runnable pass check for any step, no test data, no named pilot, no keys on the tables, no estimation formulas, and stop points that only it enforces. The security rules also point it the wrong way on classified material, and they'd put real CUI into its own model context.

What must be added before it would know (each maps to section E):
1. **Security rewrite of 00/04:** reject and quarantine classified; Grok Build never touches real CUI or keys; capture and propagate markings; FIPS crypto and a key model; encrypted backups; enforcement outside the agent; the authority to hold CUI (A1–A7, A9) → E7.
2. **One pinned tech stack and an offline install bundle** (B1, A15) → E2, E4.
3. **Typed schema with keys**, a separate inventory source, an equipment table, and a revision model with per-page change numbers (B9–B18, B26–B28).
4. **Defined reconciliation keys, a v1 normalization rule and a parser-to-table map** (B7, B8, B22).
5. **TTR and PMCS formulas**, with capabilities 8–10 explicitly deferred (B6, B15, B29, B30).
6. **Named synthetic or public-release fixtures with expected outputs, and a runnable check for each step** (B2, B3) → E3, E6.
7. **A definition of done** → E8.

## (E) What structure Grok Build needs

Recommendations only. The handoff files aren't changed.

**E1. One entry point, read in a fixed order.** *Need:* one file that says "read these, in this order; this file wins on conflict", and every other file referenced only by section. *Shortfall:* README and 00 both act as start points (README "Suggested start" vs 00 "read this first"). Three files restate the same rules in slightly different words (00 Security vs 04; 00 Known risks vs 02 Expected failure modes vs 06). Files contradict each other with no tie-breaker (04 cropped images vs 02, B24; 02 `task_parts` source, B22; 01 "ten tables" counts a view, B18). The README table lists a 07 file that doesn't exist.

**E2. Exact tech, pinned versions.** *Need:* OS and version, language and version, every library and tool with an exact version and hash (PDF lib, Tesseract plus language data, SQLCipher build with its FIPS certificate, test runner), and one database. *Shortfall:* none is named. *00 step 8* and *04 Storage* leave the "SQLCipher or pgcrypto" choice open, and *04* says "LUKS or FileVault" without naming the OS (B1, A4).

**E3. A per-step acceptance check Grok Build can run itself.** *Need:* for every build step, a command and an expected result. Examples: the network probe fails, the volume and DB report encrypted, pilot pages produce golden per-page text, parsers produce golden CSVs, `mismatches.csv` matches the expected count, loaded row counts equal CSV counts, a fixture revision pair produces the expected diff, and capabilities 1–7 return fixed answers. *Shortfall:* *00 Structure* says "validated at each layer" and *00 Build scope* says "validated before scaling" with no check defined. *02 Reconciliation* has no defined mismatch, and *05* has no expected outputs (B2, B7).

**E4. An offline dependency install plan.** *Need:* phase 0 runs on a networked machine with no CUI and produces a hash-pinned bundle (wheels, OS packages, tessdata, SBOM). Copy it over, verify it, then lock the network, with the order stated. *Shortfall:* *00 step 1* says secure the workspace "first", and *00/04* deny the network, so as written Grok Build can't install anything without breaking a hard rule (A15).

**E5. A directory layout.** *Need:* fixed paths for code (agent-writable, no CUI), synthetic fixtures, the encrypted CUI volume (agent has no access), quarantine, intermediates (per-batch key), CSV review bundle, DB, append-only audit log, backups, and TMPDIR, each with its owner and permissions. *Shortfall:* *04 Storage* and *Intermediate output* say only "same encrypted volume". No paths, owners or file permissions are given anywhere (A2, A11).

**E6. Synthetic or public test data with expected outputs.** *Need:* a named Distribution A (public-release) manual, or a synthetic TM and parts-manual pair. It should include the known traps (reused callouts, parts lists split across pages, OCR-garbled part numbers, a Change-N page, a classified-marked decoy that must be rejected), with expected CSVs and query results. *Shortfall:* *00 Build scope* and *05 Build order* say "one engine system and one symptom" but name no manual. Nothing says the pilot must avoid real CUI (B3, A2).

**E7. Hard stop points: what to halt on and what to hand back.** *Need:* each stop states its trigger, the exact report Grok Build returns (for example a missing-control list, `mismatches.csv` row IDs only, the review bundle path and hashes), and the resume signal (an approval file it can't create itself). Add stops for: a classified marking found; any real-CUI path in the agent's working tree; the network deny failing to block; unknown compilation guidance; capabilities 8–10 reached. *Shortfall:* *00 Stop points* lists three stops, all enforced by the agent itself. "Report what's missing" has no format, and "wait for Adam" has no resume mechanism. The classified, real-CUI and 8–10 stops don't exist (A1, A7, B4, B6).

**E8. Definition of done.** *Need:* "done" means the secure workspace checks pass, the pilot fixtures pass every E3 check, capabilities 1–7 return expected results on fixtures, the audit log shows the expected events, no CUI is in the code tree, logs or agent transcripts, and Grok Build hands back a run report. Capabilities 8–10 are listed as deferred. *Shortfall:* none of the 8 files defines done. *00 step 10* says "Capabilities 1–10, one at a time" even though *06* says 8–10 aren't designed (B6).
