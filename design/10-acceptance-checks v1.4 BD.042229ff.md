# 10 Acceptance Tests (one set per build step)

> **Rough bookmark, not a finished spec.** Start at `00`.
> Revised 2026-10-31: tests check an encrypted database file and a passphrase. They do not check disk encryption, FIPS, a hardware key, or SSH.

Each test checks the **software's behavior**. You run the `pytest` suites. They call the same functions the screens call. The rows marked "owner" are things only the owner can do in the app because they touch real data or his drives; he tells you the result line (PASS/FAIL, counts, error codes, hashes), never content. A FAIL means fix it before the next step.

| Test | Step | Runs | Command (illustrative) | Expected |
|---|---|---|---|---|
| C0 | Compromise check record | you | `pytest tests/test_compromise_record.py` | every package and version in `requirements.lock`, plus each native tool, has a row in `docs/compromise-check.md` with the same version; each row lists NVD, CISA catalog, vendor advisory and supply-chain sources with a UTC date; every row's result is PASS. A missing FIPS certificate is not a failure |
| C1 | Repo hygiene | you | `pytest tests/test_repo.py` | `.gitignore` contains every CUI block line from `09`; `git ls-files` lists no file matching them |
| | Data folder | you | `pytest tests/test_data_location.py` | the software refuses to create or open the database (clear error code) when `WORKORDER_DATA` is unset, points inside the repo, or points under Desktop, Documents, or another cloud-sync path; an unencrypted disk is accepted; temp files go to `tmp/` in the data folder; core file size limit is 0 |
| | Passphrase | you | `pytest tests/test_unlock.py` | the app creates an encrypted database; the right passphrase opens it; a wrong passphrase does not; the passphrase is absent from the config file, the audit log, and the database file |
| | No network | you | `pytest tests/test_no_network.py` | with sockets blocked, the pipeline and capabilities run without any connection attempt; no module in `src/` imports a network library or an SSH library |
| | Data folder | owner | Status screen | shows: database file present yes, database encrypted yes, folder outside the repo yes |
| C2 | Schema | you | `pytest tests/schema` on an empty throwaway DB in a temp folder | 9 core tables + support tables created; `parts_to_symptoms` is a view; `PRAGMA foreign_key_check` empty; every extracted table has `revision_id, source_page, change_no, marking, batch_id` NOT NULL |
| C3 | Preprocessing | you | `pytest tests/preprocess` | intake rejects non-PDF, encrypted PDF and PDF with JavaScript with exit 10; limit hit gives exit 20 and no output; markings captured before strip; page with no marking gets `CUI` + review flag; PNNORM-1 cases pass |

| C6 | Output and bundle | you | `pytest tests/bundle` | one CSV per loaded table, none for the view; formula-leading cells prefixed `'`; `MARKING.txt` present; manifest covers every file |
| C7 | Load confirm | you | `pytest tests/load_confirm` | load refuses with a clear code when the confirm is missing or wrong, when any file changed after the manifest was made, or when any mismatch count is above 0; each refusal writes an audit row `load_confirm refused`; an accepted confirm records who, when and the manifest sha256 in `load_batches` |

| | | owner | Status screen | reports the database file is encrypted |
| C9 | Revision diff | you | `pytest tests/revisions` | order comes from `publication_index`; a parsed block that disagrees becomes a review item; changes in any column are recorded; `current_*` returns the latest |
| C10 | Work order | you | `pytest tests/work_order` | a work order lists every outcome and the parts for each major defect, including mandatory replacement; on-hand quantities come from DSI, SMU, and RIP; the estimate adds the Diagnose, Repair, or Replace average for that system and adds the preference lead time once when a part is short; a missing average is shown and not invented; the defect list stacks Equipment, then Quality Control, then Maintenance, each full width; Quality Control lines have checkboxes and read `[System] - [Troubleshooting Defect]` or `Other - [free-form Defect]`, flowing left column then right column; Maintenance lines start blank and flow the same way; a checked box is saved; text written on a Maintenance line is saved and does not change the estimate; the result view shows its marking in the banner |
| | | owner | pilot run (`06` OD-5) | M1 to M5 counts all 0; capability runs return rows; the owner reports counts only |
| C11 | Backup, restore, purge | you + owner | `pytest tests/backup`; owner runs a backup and a restore from the Maintain screen | the restored database opens with the same passphrase; a purged batch folder is gone; audit rows for each |
